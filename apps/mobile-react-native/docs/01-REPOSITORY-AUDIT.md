## 2. Identity, users, roles, security and navigation

- Source: services/gateway/src/customer_auth.ts defines OTP channel capabilities, send/verify, short-lived access / rotating refresh, logout, canonical tenant-scoped session identity. The returned consumer AuthUserView has role CITIZEN; this is not evidence that all user/owner/host/agent/admin permissions are equivalent.
- Source: apps/mobile/lib/src/state/session_state.dart stores access/refresh and user in flutter_secure_storage; apps/mobile/lib/src/core/network/api_client.dart has a Dio bearer interceptor, single-flight refresh-on-401 and logout/deletion flows. Auth paths such as /auth/capabilities, /auth/otp, /auth/verify, /auth/refresh, /auth/logout are used without /v1, while many product routes use /v1. Never mechanically prefix or guess routes; require route-by-route contract tests.
- Authority: services/gateway/src/customer_auth.ts and domain authorizers parse/authorize user, tenant, Character/Twin/Host/participant/owner roles. Identity from signed server session, never arbitrary query/client claims. Admin role is separate application/authority. Consent/private/public scope and idempotency must remain server-owned.
- Main Flutter navigation: apps/mobile/lib/src/screens/twin/shell_tab.dart defines home, agents, wallet, talk; app_router.dart still redirects /chat or /chats to a private AI tab and /home query into legacy four root choices. apps/mobile/lib/src/screens/chat/chat_list_screen.dart displays AI Character threads, not a production human-only Chats root. This is documented source-vs-target drift, not a new RN design decision.
- Target: docs/APP-SHELL-CONTRACT.md and docs/END-TO-END-UX-ARCHITECTURE.md require Talks | Chats | Assistant | Wallet | Agents, exact order, center Assistant, no sixth Home, legacy deep-link and back-stack continuity. A root-tab PR #493 and broader Work PR #497 are DRAFT/UNVERIFIED at this audit; do not count their work as merged main or duplicate their Flutter ownership.
