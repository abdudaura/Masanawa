# UI audit: copyable next-window prompt

Use the following to start the next available audit window. A finishing window prints it directly with the selected ID, predecessor handoff and exact delivered SHA already filled from its evidence. The seed deliberately chooses from fresh source, rather than pinning a forever-stale branch or release claim.

```text
Continue weavewellindustrieslimited/masanawa from fresh origin/main.
Read AGENTS.md, CONTINUE-HERE.md,
docs/workstreams/UI-CONTINUATION-QUEUE-20261012.md and
docs/workstreams/UI-NEXT-WINDOW-PROMPT-20261012.md.
Then read only the selected milestone's handoff and relevant parts of
docs/superpowers/specs/2026-10-12-masanawa-ui-audit-design.md and
docs/superpowers/plans/2026-10-12-masanawa-ui-refinement.md.

Complete the next dependency-ready UI audit milestone. Prefer continuing
unfinished claimed-source work through its existing PR when ownership is
available; otherwise start the earliest unclaimed ready item in the queue.
Initial preference is MUI-01 shared headers/navigation/search presentation;
MUI-02 auth language centering can run independently. Recheck current main,
PR heads, unique branch source and factory/claims before selecting or coding.
If another window owns the required paths, choose a disjoint ready item or
publish the smallest needed transfer/dependency; never overwrite its source.

Preserve Chats · Status · Wallet · Calls · Rooms, Chats launch default,
Masana-only contacts and all delivered native/group/history/billing/incoming
calls. Do not restore Twins, human-to-human consumer calling, live-Talk Status
or unsupported user publishing/Create Room. Reconcile Status/Rooms branch
work selectively; do not replace the full newer Calls screen with a scaffold.
Reuse existing authenticated inbox/history/feed/Rooms and canonical wallet
contracts. No fake records, balances/rates, second ledger or Cr-to-MSN relabel.

Implement connected requested behavior, not another recommendation report.
Claim exact paths under the existing AF owner; coordinate shared composition.
Fix/test/review/commit/push and merge compatible source into main. Keep real
checks, branch protections, auth/privacy and financial authorization. Run
checks relevant to the changed source, fix introduced failures and report
baseline/unavailable checks honestly. Do not require unrelated full-product
or provider qualification for a development source merge. Paid execution,
destructive migrations and production activation remain separately authorized.

Keep implementation, executed verification and installed/release evidence
separate. Inspect real mobile layouts for visual claims; preserve existing
financial validations and uncertain-operation recovery through wallet sheets.
If a runner/dependency blocks one acceptance, record the exact missing input
and continue independent runnable source instead of repeating blocked work.

Update/create the selected UI-MUI handoff using
docs/workstreams/UI-WINDOW-HANDOFF-TEMPLATE-20261012.md. Include exact base,
source/main SHAs, PR, paths, commands/results, all open acceptance and the
smallest next action. Release ownership. Give the owner the result and the
next continuation prompt DIRECTLY, naming the next ready milestone and its
handoff and retaining UI-CONTINUATION-QUEUE-20261012.md in that prompt.
Repeat until MUI-01…08 are integrated and verified, then complete MUI-09
combined regression/visual checks and MUI-10 installed signed-app checks.
Do not claim the audit complete while any requested acceptance remains open.
```

For an already-directed lane such as signed incoming-call qualification, append this short paragraph to its existing prompt rather than replacing its task:

```text
Also read docs/workstreams/UI-CONTINUATION-QUEUE-20261012.md. Preserve the
audit's shared design/search contracts in touched screens. Record relevant
UI acceptance in this lane's UI-MUI handoff. If your device/provider check is
blocked, continue independent source work in your lane where ownership is
available (Calls: MUI-05 search), keeping qualification explicitly open.
At handoff include the queue link and name the next ready audit milestone
in the next copyable prompt so pending audit work is not lost.
```
