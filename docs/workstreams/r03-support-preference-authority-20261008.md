## Exact implemented source / authorized journey

1. **Database/migration:** reuse canonical `packages/agents/migrations/0004_platform_agent_preferences.sql` (`agents.user_agent_preferences`, `agents.platform_agent_profiles`) and existing PostgreSQL repositories. No new schema or migration required for the narrowly scoped preference; keep tenant/user composite keys and existing revision compare-and-set. The admin's original support profiles, live voice model, and public AI Seat qualification are not altered.
2. **Gateway / API / authorization:** existing authenticated `PUT /agent/preferences/default` and `GET /agent/directory`. The write service requires the authenticated customer's tenant/user/allowlist, verifies target is in the *current tenant's visible presentations*, verifies canonical profile `supportAgent`, and reuses persisted user's preference. Same-choice duplicate PUT is idempotent. New writes use existing revision CAS, reread `readForUser({tenantId,userId})`, and refuse success when readback differs. Malformed ID/hidden/non-support/unknown write errors have bounded HTTP 400/404/409/503 via existing Gateway error handler without SQL/secret details. Admin-hidden agents cannot be selected by a stale mobile cache.
3. **Flutter:** existing `AgentDirectoryTransport` and auth-refresh HTTP adapter perform the same authenticated PUT/GET; `AgentDirectoryController.changeDefaultSupportAgent` fences active account, validates candidate from present authenticated roster, serializes obsolete directory loads using request generation, reads back one canonical selected support agent before mutating state/secure per-account roster cache. Network/revision/unknown outcome leaves previous selection visibly unverified with Refresh; app never claims saved from PUT alone. Sign-out while pending suppresses old user's result; cache failure is non-authoritative.
4. **Settings UI:** existing radio selection disables while loading/saving/unverified, offers Refresh, prevents double action, and shows success only after authoritative GET and stable owner. Session switch suppresses old-account snackbar. Existing support-persona chat, other app tabs, sound and Wallet are unchanged. No mock/disconnected production endpoint was introduced.
5. **Offline/restart:** last verified account-scoped directory can restore from cache on startup with *unknown presence*. No offline preference write: user must return online and refresh before choosing. Uncertain PUT is resolved by GET rather than another blind write. Existing auth signing/logout/token refresh and DB persistence are reused, not reimplemented.
6. **Tests authored only:** 8 service cases for auth/allowlist/hidden/cross-tenant/non-support/invalid ID/idempotence/readback, HTTP request-schema/error status cases, 6 Flutter controller state/logout/retry tests, 2 Settings widget tests for slow save and failed readback.
