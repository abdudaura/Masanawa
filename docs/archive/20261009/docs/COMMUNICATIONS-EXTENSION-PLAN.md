## 1. Product outcome and preservation contract

Masanawa combines (a) **simple human communication**, (b) **public human-hosted audio Talks and creator earning**, (c) **native fiat/Credits/creator earnings and qualified cryptocurrency**, and (d) **Gwani/Gwana able to complete authorized work throughout the app**. Any supported task is available by **voice, typing, or hands-on controls**. People who cannot comfortably read or type can still complete voice-capable tasks; someone who cannot speak aloud can use identical silent controls. ## 4. Exact end-to-end journeys (release requirements)

### 4.1 Person to person, both quiet and voice
- User searches a public handle or chooses a consenting saved contact, opens a private DM from person profile/Chats, sends text, sees pending then delivered after server ack; recipient receives and reads with appropriate notification setting; both can reopen history after device restart.
- Another user records a voice note, reviews and sends it; recipient streams/plays it. Mic denial, upload failure, backgrounding, playback and privacy-safe retry work. Replies/attachments use the same authenticated conversation and server membership.
- Block/report prevents subsequent DM delivery according to documented policy and revokes media access. Private content is **never** silently included in public Talk/AI context.
- Future groups and person-to-person calls are **later explicit phases** after verified 1:1 text/voice; document concrete scope and ownership when selected, not silently pretend they are shipped or redesign navigation in advance.

### 4.2 Fast history without manual restore screens
- Open the shell quickly; cached recent chat list and first page of a cached conversation render immediately, even while offline, then sync deltas in background. A fresh device can securely fetch authorized history from the server; **manual backup/restore UI is not a requirement**, but durable persistence and sync are.
- Local database is indexed per account/conversation/time; cache is protected at rest and purged on sign-out, account deletion, access revocation or profile switch as policy requires. Limit disk/media budgets, clear cache separately from server deletion, recover from corrupt cache safely.
- Use cursor pagination (initial page target 30–50 messages, tuned by measurement), append older pages on scroll, keep scroll position, avoid full-history memory/download, fetch media on demand and measure bytes/CPU/frame time. Stale cache cannot authorize sending money.
- Target **cached Chats list <1 second p95** on warm navigation and **cached thread <500 milliseconds p95** on tap, measured on named affordable Android device/build; these are provisional targets to profile/adjust with evidence. Include cold start, 1,000 conversations/100,000 historical messages fixtures, low bandwidth, airplane mode and multi-account isolation. No instant-success claim based on static code.

### 4.3 Wallet and transfers in a chat
- Select Send from a DM or say/type “Gwana, send 20 USDT to Amina.” Resolve **exact authenticated recipient**, choose qualified asset and network, use server balance/fees/limits/quote, read/show meaningful exact terms, require fresh explicit confirmation and risk-based authentication, settle once on the existing ledger, show sender/recipient receipts and clear failure/pending states.
- If “him” refers to the currently opened chat, display/read the specific person before authorizing; ambiguous nicknames ask once, never guess. Money instructions are private, even while listening to a public Talk. No silent sending because of a model guess, a “yes” from another context, a replayed recording or a stale quote.
- Qualified external on-chain withdrawals remain separate from in-platform transfers. No unsupported currency/network/provider promises, no hidden exchange, no app-local balance authority, no duplicate charge on retry.

### 4.4 Everywhere AI is an operator
- From any normal screen, invoke Gwani/Gwana privately. Actions are deliberately typed, spoken or tapped, sharing task state, read-back, idempotent execution and receipts. Assistants can send authorized messages, manage the user's Talks under Host authority, access qualified Billing/Crypto and explain earnings, but cannot override moderation, bypass authentication, move funds without consent or search all human private messages without narrowly scoped user action.
- Voice is first-class with multilingual/code-switching, real native audio, barge-in, repeat/correct/slower and spoken amounts, but microphone requires deliberate activation. Full keyboard-only/tap-only path functions even in quiet spaces and with denied microphone.
- Separate context explicitly: private DM, private assistant task, public Talk Host/Speaker/Audience and private Direct Twin are distinct authorities. No cross-stream audio, prompts, receipts or sensitive data.
