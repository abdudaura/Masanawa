# Multi-window coordination

Updated 2026-10-11 by explicit owner direction. Main is the default development
integration target; this supersedes older integration-only delivery rules.

## Work efficiently

Inspect fresh main, actual affected source and relevant branch work. Read only
contracts needed for the task. Preserve local updates and useful existing PRs.
Choose a connected customer milestone or reproduce a concrete blocker.

Publish exact-path ownership in the existing registry before implementation.
Keep one owner for contested routing, auth, money and migration files. Request a
narrow transfer when needed; do not seize another window's source. Released or
expired records require visible recovery and preservation of unique branch work.
A useful source checkpoint renews ownership; empty heartbeat commits do not.

## Integrate into main

Use a scoped feature branch/PR and merge compatible changes promptly into main.
The owner authorizes routine development CI/CD triggered by merging main.
Do not create integration queues merely to avoid development deployments.
Use an alternate target only for a concrete conflict or explicit owner direction.

Review the changed source, conflicts and relevant authorization/failure behavior.
Run checks relevant to the change. Fix introduced failures; document unrelated
baseline failures and unavailable runners. Keep real tests and branch protection;
do not suppress regressions or use admin bypass. Documentation-only changes need
diff/link review, not full app builds. Full device/provider/backup/release proof is
not a prerequisite for every development merge.

Keep canonical financial/auth/privacy safeguards and secrets. Destructive data
migrations, paid resources, provider spending and external messages still need
applicable authorization. A development merge/deployment does not establish a
production-qualified release.

Leave a concise handoff: branch/PR, base/head, changed paths, executed results,
remaining dependencies and next action. Do not require full-app source closure
before a scoped PR or useful local test handoff. Report source, integration,
device/provider qualification and deployment evidence separately and honestly.
