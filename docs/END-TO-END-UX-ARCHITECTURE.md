## 1. Unambiguous permanent information architecture

**Exactly five bottom tabs, left to right: Talks · Chats · Assistant · Wallet · Agents.** Assistant is centered (index 2), with two tabs on either side. It is visually prominent as the primary AI action without intercepting accessibility or navigation, auto-recording or covering content.

| Tab | Unique purpose | Default screen and actions | Explicitly NOT this tab |
| --- | --- | --- | --- |
| **Talks (far left)** | Discover, listen, participate in and host **public human-led audio Talks** | Explore and Live Talks as subfilters; single-column vertical cards/replays; **Start Talk** FAB opens public composer, later explicit Go Live | No redundant Home bottom tab; not the private Gwani/Gwana chat; not general text posts |
| **Chats (left of center)** | Private person-to-person messaging | Human conversations, unread/pending states, secure text, voice notes, media and **New message** | No AI agent threads mixed into human DMs; no public audio room; composer Send does not transfer money |
| **Assistant (CENTER)** | **One private chat interface** with switchable **Gwani** and **Gwana**; operate Masanawa using voice, text or tap | A single familiar, fast chat UI with explicit agent identity switch, talk/record vs type controls, task cards and full action/recovery states | No independent Gwani and Gwana root tabs; no public Talk audience; no auto-microphone and no silent action |
| **Wallet (right of center)** | Money, eligible Billing/Crypto, creator earnings and transaction evidence | Separate fiat, Credits, crypto per asset/network, pending/available earnings; qualified shortcuts, funding, send and receipts | No merged fictitious balance; no duplicated payment pipeline; no mandatory AI wait to read status |
| **Agents (far right)** | Find **Masanawa Agents/Experts** and **Twins**, view profiles, discover/add to Talks, own/teach/manage My Twin | Visible 'Masanawa Agents' and 'Twins' discovery modes, search, availability, private persona interaction, paid Seat quote/confirmation where eligible | Not the universal Gwani/Gwana Assistant tab; not a Home content feed; no silent paid Seat on browsing |

**No Home bottom navigation destination.** Former Home Explore/Live feed moves to **Talks**, keeping the same public Talk semantics, feed items, host controls, human presence, ranking and replay identity. A legacy '/home' path must still work, but it is not a visible sixth destination. No general-purpose home dashboard or duplicate carousel.

**Assistant and Agents are distinct**: Assistant is the one privileged, private Gwani/Gwana operator workflow with a visible in-chat Gwani ↔ Gwana switch; Agents is a **directory** of 17 approved server-managed Experts plus public Twins, personas/roles/availability, owner Twin management and eligible Talk Seat additions. Ordinary private conversations with a discovered Expert/Twin can open from its own profile without turning it into a second central operator or inheriting Assistant permissions. Platform/creator persona boundaries, pricing and AI disclosures remain.

**Talks and Chats are distinct**: public audio stages (moderated, recordable/replayable according to settings, human Host mandatory) vs protected private messages between authenticated people. Person-to-person message, public invite, free human Seat, and paid AI Seat are different actions.

**Inherited invariant rules**: exactly two standalone service families Billing/Crypto; qualified internal user-to-user crypto sends are an operation within Crypto. Wallet's fiat, Credits, earnings and crypto remain separate. White/light WhatsApp-like vibrant green, approved logo, lightweight controls, multilingual UI/RTL/low literacy, WhatsApp/Telegram channels and existing R01–R19 feature/compliance gates remain.

## 2. Shared shell: layout, safe area and primary actions

- Bottom bar items in exact order **Talks | Chats | Assistant | Wallet | Agents**; Assistant occupies geometrical center and gets an intentional (not giant/overlapping) emphasized active treatment and accessibility label. Every tab has stable labels/icons, notification unread counters only where relevant, dark-mode-independent white/light default, reduced motion, safe-area and keyboard handling. On 320–360dp/large text/RTL, keep all five destinations discoverable: measure label wrapping, tap targets, icon sizes and scrolling; do not silently drop or hide a tab.
- Header shows **Activity bell** and **profile avatar** on normal roots; contextual **Search** on Talks, Chats and Agents where appropriate; support immersive Talk/assistant header adaptations. Header avatar → You/Profile/Settings/My Talks/My Twin/Earnings; bell → Talk/social/payment/platform Activity (not a duplicate full DM inbox).
- **Talks** alone has green **Start Talk FAB** opening the public Talk creation screen, NOT immediately broadcasting. **Chats** instead has clearly labeled **New message** icon/FAB (one action only); **Assistant** has its built-in mic/type composer and agent switch, no Start Talk FAB; **Wallet/Agents** have contextual actions, not inherited global Start Talk FAB. Hide FAB while keyboard/sheets/audio controls would overlap.
- Contextual 'Ask Assistant' affordance on relevant screens safely opens the **same private assistant task**, no second permanent large floating button overlay. From a live public Talk it must isolate private audio, responses and financial data; no public capture or playback of private messages. Return preserves public listening role safely.
- Header, deep links, search and screens respect authenticated session, owner privileges, permissions and real server capabilities rather than showing fake buttons.

## 3. Talks: public audio, including previous Home's full discovery

- Talks landing includes **Explore** and **Live Talks** sub-tabs (or equally clear chips). Explore: one vertical list of full-width live/replay/followed/recommended Talk cards. Live: only currently live. No horizontal Talk rails/grids; category filters may scroll horizontally but Talk cards may not.
- Search can discover Talks, people, Experts and Twins with explicit result types. Person/profile and persona links retain canonical IDs; opening a card → same public Talk route and role-specific controls.
- Listener: listen, react, ask, raise hand, gift, share, request an AI Seat; Host/Speaker/Director gets strictly authorized moderation, human invitations, Expert/Twin sponsorship and audio settings. No AI-only public Talk, max active Seat policy (currently 6 total/3 AI by canonical policy), human Seats free, paid AI Seats quote/confirm. Host departure/reconnect leads to accurate pause/end. Replay controls replace live interactions appropriately.
- Creation: prominent Start Talk → concise composer with optional human/AI invite, privacy/replay settings where supported → explicit Go Live, microphone/LiveKit permissions/errors/reconnect. 'Add Expert', 'Invite Person', 'Add My Twin' retain real working flow and fee consent, draft preservation and back navigation. Creator gifts/earnings and recording are public Talk features, not transferred to private Chats.

## 4. Chats: human DMs only, familiar lightweight conversation UX

- Chats root shows private real-person threads with avatar, verified handle/display name, preview/timestamp, unread/notification mute states and server-acknowledged sending/read statuses. Search and **New message** lead to privacy-aware human discovery; optional phonebook import only with informed opt-in. Missing contacts, blocks, requests, self-messaging and revoked permissions return truthful states, not phantom chats.
- Person profiles have responsive **Message** alongside Follow/Listen live where qualified. The DM can include explicit **Invite to public Talk** if acting as an authorized Host, but Message alone never grants an audio Seat. One-on-one person chat is the committed scope: groups, human voice/video calls remain a separately approved expansion; no inert call icons.
- DM thread: classic compact composer with text, emoji, attachment and deliberate microphone/voice-note record-review-send. Message arrow sends **messages**, never money; extra **Transfer** action invokes the same Wallet eligible internal crypto transfer task with recipient prefilled but **not authorized**. Bounded signed media upload/access, content limits, lifecycle, retry and privacy controls apply.
- Server-backed ordered pages, token/cursor resume, per-account protected indexed cache, honest pending/offline drafts, lazy media, realtime catch-up, push links, correct two-device read/delivery state and account switch/logout revocation. **No artificial manual backup/restore step**. C05 provisional warm cached list <1s p95 and cached thread <500ms p95 on named low-end handset; benchmark 1,000 chats / 100k historical messages, airplane/weak network, bytes/frame time/cold start, not unproven promises.
- Keep **person DMs separate** from an AI persona thread, the private Gwani/Gwana Assistant session and moderated public Talk comments; never put protected human chat content into generic model context.

## 5. Assistant: one central Gwani/Gwana conversation and one action authority

- **One root Assistant chat surface**, not independent Gwani and Gwana navigation screens. The chat header shows the currently active persona and a clearly labeled **Switch to Gwani / Switch to Gwana** chooser **inside the existing conversation UI**. Both support voice-first **and** complete typing/tap paths with common task cards and attachments. No model/provider/token setup exposed to consumers.
- **Switch policy to freeze before code**: one durable user-owned assistant workspace/task timeline; each message and reply is attributed to its real Gwani/Gwana persona, current selection is explicit and persisted per user session. Switch never duplicates messages, changes recipients, executes outstanding approvals, or clears a draft; active financial or destructive confirmations remain attached to the original task and server authority and require fresh confirmation if context/persona changed. Conversation-visible history may be reused inside this single authorized assistant workspace; it is NOT permission to read unrelated human DMs or AI/Twin private conversations. The server determines accessible context; no cross-account leakage. The user can switch back without new chat or app reset.
- A user who asks 'Gwana, send a message to Ibrahim' enters a deliberate draft-review-send workflow with resolved recipient and idempotent delivery. 'Gwani, transfer five USDT' enters an authenticated exact quote/fees/network/recipient read-back and fresh approval task; neither model guesses consent, address, pricing, KYC, eligibility or outcome.
- Gwani/Gwana can, subject to scopes, search person/Expert/Twin, create/invite/manage Talk under Host rights, explain gift/earnings status, quote bills/crypto/funding/transfer, edit profile/settings when authorized, and return files/results. Voice, text and taps share one typed action/session/task ID and server execution ledger. Read-only commands work when mic denied; qualified financial work never executes offline.
- Voice: deliberate mic start, interrupt/repeat/correct/slower, qualified native Gemini Live, no browser-TTS substitute, no background listening. Switching persona must not replay stale audio or transfer microphone permission to a public Talk. Use clear private mode indicator while a live public Talk is in background.
- Agents directory's non-Gwani/Gwana persona conversations are separate character-thread views with their own identity, privacy and ability scope; interacting with an Expert does not silently grant global Assistant financial authority.

## 6. Wallet and Agents: exact positioning

**Wallet**: top-level account-qualified balance summary with four separately labeled financial types (fiat by currency, Credits, crypto asset/network, earned pending/available). **Crypto** shortcut first; then **Data, Airtime, Electricity, TV/Cable**; history, Add money, Send (fully disambiguated, e.g. 'Send crypto to Masanawa user'), external Withdraw, creator earnings/receipts where supported. Read-only views must load without agent/provider cold start. All taps/speech share server-owned quote → terms → explicit fresh auth/confirmation → once-only idempotent settlement → immutable receipts → pending/unknown/failure/reconcile. No cross-asset or fiat/Credits/crypto auto-conversion; on-chain external withdrawal is distinct from internal ledger transfer.

**Agents**: the dedicated fifth tab preserves the original Agents root discovery **Masanawa Agents | Twins**, including the full 17 personas, role/presence/search/private persona chat, public and owner Twins, My Twin creation/training/settings/earnings, and the conditional invite/hire/add to public Talk action. People human chat is in Chats, not Agents. Agent tap must distinguish **View profile**, **Chat privately**, **Add to Talk / Sponsor Seat** with exact price and Host approval as required. Do not bury Agents/Twins in Chats or Settings; no new sixth personal Twin root.

## 7. Router and identity compatibility: lock this before parallel coding

Current code evidence at review: Flutter '/chats' redirects to '/home?tab=talk' **private AI**, '/chat/:id' is an **AI character ID**, '/home?tab=agents' selects Agents, and Start Talk FAB appears on former Home+Agents. These are historical code facts, **not** permission to repurpose either '/chats' or '/chat/:id' as new human messages without explicit compatibility migration.

**Proposed stable destinations / required aliases:**
- '/talks' → new Talks root Explore/Live; existing '/home' and '/home?tab=home' → Talks root. Keep '/talk/create', '/talk/:id' and public replay/deep links unchanged.
- '/messages' → **Chats root for human DMs**; '/messages/:conversationId' → authenticated member-only one-to-one thread; '/messages/new?...' prefill is untrusted and must be verified against recipient, request, block and identity policies. **Legacy '/chats' stays a private AI/Assistant alias** unless a separately proven versioned migration changes external link semantics.
- '/assistant' → Assistant central private Gwani/Gwana workspace; legacy '/home?tab=talk', '/chat' and historical '/chats' root redirect here. '/chat/:characterId' remains an AI character thread, never a human DM. Preserve exact character/deep link resume for a private Expert/Twin chat.
- '/wallet' and legacy '/home?tab=wallet' → Wallet; '/agents' and legacy '/home?tab=agents' / '/masana' → Agents. Keep '/persona/:publicId', '/my-twin', '/u/:handle', '/activity', '/you', '/settings', '/crypto', '/billing' and receipt links functional.
- Preserve legacy '/home?tab=create', '?tab=activity', '?tab=you' actions to their existing targeted pages. The old tab integer indices **must not be reused as semantic aliases**; persist named destination keys, update state restoration and deep link handlers. Root notification click must authenticate first and then restore the correct typed destination.
- **Typed identity**: PersonRef (authenticated stable account/public handle resolution), PersonaRef (verified Expert/Twin character/public ID), ConversationRef (server-authorized human DM), TalkRef (public stage), TaskRef (assistant/wallet operation). Never coerce display names, person IDs, character IDs, talk IDs and wallet recipients because the strings look similar.
- One integration owner edits Flutter shell/router/localization plus shared push/deep-link registration; independent R17/C02/C03/C07/C08 lanes provide APIs/contracts and tests, not competing edits to shared paths.

**Navigation/back proof**: Talks feed → public Talk → private Assistant → back same live Talk role/scroll; Talks feed → public Talk Host → Invite Person → DM composer → back same Talk; person profile → human DM → back profile; Chats → DM → qualified Transfer quote → receipt → same DM; Wallet → bill shortcut → Assistant task → receipt → Wallet; Agents → Expert profile → private AI thread → Agents scroll; Assistant Gwani → Gwana → Gwani retains allowed history and no duplicate task or approval. Push → auth → correct DM/public Talk/receipt/AI persona route. Reopening views neither turns on mic nor executes spending. Test Android system back, deep links, interrupted audio, memory reclamation and account switch.
