# Reusable implementation prompt

Use this in continuing windows. Prefer reusing existing windows; a unique ID and live path claim are still required. An already active root integrator is not replaced.

```text
MASANAWA — COMPLETE A CUSTOMER MILESTONE

Window ID: auto-generate a unique ID; never reuse an active owner's identity.
Repository: https://github.com/Baatiku/masanawa
Factory: https://github.com/Baatiku/Software-Factory-starter-kit

Read fresh main CONTINUE-HERE.md, AGENTS.md, docs/NEXT-WAVE-DELIVERY-20261010.md
and the latest accessible Factory SKILL.md/AGENTS.md/relevant references.
Then read only the feature contracts, screen states, recovery inputs and AF lane
needed for your chosen milestone. Preserve all confirmed product requirements.

Inspect live factory/claims registry, relevant PR heads/files/handoffs and actual
toolchain access. Continue a substantive existing unfinished feature before
opening another narrow patch. Select the highest-priority unclaimed customer
milestone in the delivery document and claim exact paths; dependencies block
only their specific contracts, not all independent implementation.

Do not create another evidence validator, cleanup engine or isolated guard
when an existing authority can be extended. A safeguard is justified by a
demonstrated acceptance/security blocker; it does not complete the parent lane.
Do not select easier helper work while essential user features are untouched.

Implement the milestone as connected source: repository/database, authenticated
API, real canonical adapters, client state/UI/navigation hooks, all important
failure/offline/permission/retry states and meaningful tests. Reuse existing
draft implementations. Financial actions use one ledger and explicit user
authorization; phone numbers without ownership proof remain unverified.

Coordinate bounded shared-file transfers for required composition with the
current owner. Root integrator AF00 and protected authorities remain singular;
do not seize shared files or independently start a competing integration branch.
Missing local APK/source does not block independent work, but cannot be claimed
reconciled or overwritten.

Run relevant tests on exact committed source. Obtain/use a permitted executable
toolchain where possible. If unavailable, record the exact command/environment
blocker once, assign actual execution to a capable runner/window, and continue
implementable source. Do not keep retrying no-step CI or count static inspection
and rewritten simulations as repository tests.

Finish and test coherent connected increments in one continuing PR. Merge
compatible source-tested work promptly into the single reviewed safe integration
baseline; source review/merge may be delegated for non-overlapping paths.
Production/device/provider gates remain separate. Never force through failing
or unverified unsafe code, implicitly deploy or spend on providers.

For every waiting PR provide its exact head, concrete blocker, responsible owner
and next executable correction. Do not stop at a small guard or handoff if the
customer milestone still has implementable missing source. Continue that work.
If genuinely blocked, preserve precise handoff and claim an independent critical
milestone rather than invent a new helper.

Before ending, update the parent milestone's finite closure checklist under
docs/NEXT-WAVE-DELIVERY-20261010.md: exact source item/paths, implementation
owner/commit, remaining source, integration SHA and separate execution result.
Close implementable source and composition HERE before the owner pulls locally.
An absent runner defers only its execution checks; never missing code, routes,
migrations, adapters or conflicts. Continue the next essential open checklist
item, or explicitly transfer it in this same PR if the session must end.
AF00 publishes one integration target and delegates bounded composition.
Do not ask for local pull until all required source is implemented and integrated;
provide exact capability blockers and local test/build commands without claiming
unrun checks passed. Preserve and later reconcile the owner's unseen local fixes.

Report: customer journey now supported, source still missing, exact commands
and actual results, base/head/PR, integration target/status and precise activation
gaps. A partial patch, placeholder destination or passing evidence checker is
never “lane complete” or proof the APK/product works.
```
