# Source Map — OpenClaw

Pinned: `83e4755b55e8864e48348f3eb2364ee3e5f0fb54`.

Status: Phase 0A initial map; deep mining required.

OpenClaw is a major donor, not merely a skill library.

Key areas to evaluate:
- local-first Gateway as control plane for sessions, tools, events and channels;
- WhatsApp, Telegram, Slack, Discord, Teams, iMessage and 20+ channel ecosystem;
- native/device nodes adding voice, camera, screen and local actions;
- isolated per-agent workspaces/session stores and explicit channel-account bindings;
- multi-agent team/delegation structures;
- integrated model discovery/tool wiring/prompt/session/channel runtime;
- steering/follow-up/collect/interrupt behavior for inbound messages during active runs;
- skill roots, precedence, per-agent/shared scopes, gating, install/update/verify, workshop and ClawHub distribution;
- tool policy, sandbox/security and operator approval;
- local-first state/credentials;
- memory files + hybrid search engines, action-sensitive memory, compaction flush, dreaming and provenance-rich memory wiki;
- cron/intents and persistent automation.

Important Masanawa caveats:
- OpenClaw is fundamentally an assistant/workspace product; Masanawa needs multi-user character relationships and shared world state.
- SQLite/Markdown memory is not Masanawa canonical storage.
- OpenClaw's integrated runtime boundary must not cause Masanawa to collapse identity, workflow or financial truth into an agent loop.

Likely donor areas: gateway/channels/device nodes, workspace/session isolation, skills distribution/trust, execution steering, local-first operations and selected memory maintenance patterns.
